# AlchimistWorld

Настольное приложение-помощник по homebrew-алхимии для D&D-кампании: ведёт учёт реагентов и
зелий, показывает, что можно сварить из того, что есть, чего не хватает до известных рецептов,
и хранит журнал экспериментов.

Механика, требования и архитектура описаны в [`docs/`](docs/README.md) — код следует им.

```
┌───────────────┬─────────────────────────────────────────────────┐
│ Могу сварить  │  [поиск.....................]    Набор: Алхимик │
│ Почти готово  ├─────────────────────────────────────────────────┤
│ Лаборатория   │  Зелье Лечения (Слабое)            обычное   ×3 │
│───────────────│    Жидкая · Подлуннух + Свечная Роза  [Сварить] │
│ Реагенты      │    Жидкая · Могильная Лоза + Мыльная Трава      │
│ Мои зелья     │  Алхимический Огонь                обычное   ×1 │
│───────────────│    Любая · Тусклая эссенция огня      [Сварить] │
│ Справочник    │                                                 │
│ Журнал        │                                                 │
│───────────────│                                                 │
│ Настройки     │                                                 │
└───────────────┴─────────────────────────────────────────────────┘
```

## Установка

Нужен Python 3.12 или новее.

```bash
python -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
.venv/bin/python tools/i18n.py compile
```

С `uv`:

```bash
uv venv && uv pip install -e ".[dev]" && uv run python tools/i18n.py compile
```

Готовые сборки для Windows и macOS — в [релизах](../../releases); под Linux удобнее `pipx install .`.

## Первый запуск

```bash
.venv/bin/alchimist-gui
```

Сначала откроется окно создания персонажа: имя, наборы инструментов и тема (по умолчанию тёмная).
Справочник кампании встроен в приложение: новый персонаж знает все реагенты и рецепты обычных
зелий, остальные изучает кнопкой «Изучить рецепт» в «Справочнике».

Персонажей может быть несколько — у каждого свои наборы, реагенты, зелья, журнал и изученные
рецепты; переключаются они в **Настройках**. Справочник правит только GM: он встроен и скрыт,
а добавляется, если при создании персонажа ввести имя **GM**. GM рассылает справочник файлом
(**Настройки → Экспорт справочника**), игроки его принимают (**Импорт справочника**).

Подробнее — в [инструкции для игроков](docs/05-для-игроков.md).

## Консоль

Всё, что нужно для игры, есть и в терминале:

```bash
alchimist new-character Гримли      # создать персонажа (имя GM — мастер)
alchimist characters                # список персонажей, * — активный
alchimist switch Гримли             # переключиться
alchimist learn "Пламя Саламандры"  # изучить рецепт (--forget — забыть)
alchimist inv add "Щёлкорех" 3      # пополнить инвентарь
alchimist inv show                  # что в сумке
alchimist can-brew                  # что можно сварить
alchimist almost --max-missing 1    # чего не хватает
alchimist journal                   # журнал
alchimist check                     # проверить справочник по правилам
alchimist settings --kits herbalist # наборы активного персонажа
alchimist export catalog.json       # отдать справочник партии (только GM)
alchimist import-catalog catalog.json --dry-run
```

Полный список — `alchimist --help`.

## Где лежат данные

| ОС | Данные | Настройки |
|---|---|---|
| Linux | `~/.local/share/AlchimistWorld/` | `~/.config/AlchimistWorld/settings.toml` |
| Windows | `%LOCALAPPDATA%\AlchimistWorld\` | там же |
| macOS | `~/Library/Application Support/AlchimistWorld/` | там же |

У каждого персонажа своя папка `profiles/<id>/`, справочник общий — `catalog/`.
Переменная `ALCHIMIST_DATA_DIR` переопределяет папку — удобно для «портативного» режима и тестов.

Файлы — обычный JSON и TOML: их можно править руками и держать в git. Перед каждой перезаписью
делается копия `.bak`, запись атомарная.

## Устройство

```
src/alchimist/
├── core/        модели, правила, подбор — только стандартная библиотека
├── storage/     JSON и TOML, миграции, атомарная запись
├── services/    сценарии и шина событий
├── i18n/        gettext и тексты по кодам предупреждений
├── data/        встроенный справочник кампании
├── cli/         консольный интерфейс
└── ui_qt/       PySide6 — заменяемый слой
```

Ядро не знает ни про Qt, ни про файлы, интерфейс не знает про хранилище. Границы проверяются
`import-linter` в CI и перед коммитом, так что GUI можно переписать (GTK, TUI, веб), не трогая
логику.

## Разработка

```bash
.venv/bin/python -m pytest                      # все тесты
.venv/bin/python -m pytest --ignore=tests/ui_qt # только ядро, без GUI
.venv/bin/ruff check src tests
.venv/bin/lint-imports --config pyproject.toml  # слои
.venv/bin/python tools/i18n.py update           # обновить .po
```

Хуки перед коммитом: `pre-commit install`.

## Сборка

Подробности — в [packaging/README.md](packaging/README.md).

**Поставить себе** (Arch, CachyOS, Manjaro): пакет весит килобайты и берёт системный Qt.

```bash
cd packaging && makepkg -si
```

**Отдать другому на Arch/CachyOS** — готовый пакет, получатель ставит одной командой
`sudo pacman -U alchimist-world-*.pkg.tar.zst`:

```bash
cd packaging && makepkg -f
```

Если makepkg пожалуется на недостающие зависимости для сборки (`python-build`, `python-hatchling`
и т. п.), добавьте флаг `-s` — он доставит их через pacman, а `-sr` ещё и уберёт после сборки:
`makepkg -sf` или `makepkg -srf`.

**Отдать кому угодно** — самодостаточная сборка, у получателя ничего ставить не надо:

```bash
python packaging/build.py --onefile
```

Результат в `dist/`: папка, архив и вариант «одним файлом». Собирать надо на той ОС,
под которую нужен результат, — PyInstaller не умеет собирать под чужую систему.

**Windows-сборка с Linux** — через Wine (`packaging/build-windows-wine.sh`) или, надёжнее,
через GitHub Actions по тегу `v*` (`.github/workflows/release.yml`): там сборка идёт на
настоящей `windows-latest`.
