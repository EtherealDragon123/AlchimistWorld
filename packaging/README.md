# Сборка и установка

Коротко: **под свою систему** лучше ставить пакетом, а не самодостаточной сборкой —
она в сотни раз меньше и обновляется вместе с системным Qt. Самодостаточная сборка
нужна, когда приложение надо просто **отдать человеку**, у которого ничего не стоит.

| Что в папке | Зачем |
|---|---|
| `build.py` | Сборка под ту ОС, на которой запущен. Одна команда |
| `alchimist.spec` | Описание сборки для PyInstaller, общее для всех ОС |
| `build-windows-wine.sh` | Windows-сборка на Linux через Wine |
| `PKGBUILD` | Пакет для Arch и производных: CachyOS, Manjaro, EndeavourOS |
| `alchimist.desktop`, `icon.*` | Значок и пункт в меню приложений |

## Своя система: Arch / CachyOS

```bash
cd packaging && makepkg -si
```

Соберёт и поставит пакет `alchimist-world` (~350 КБ). Подтянет из репозиториев
`pyside6` и остальные зависимости, добавит значок в меню. Удаляется обычным
`sudo pacman -R alchimist-world`.

## Отдать другому на Arch / CachyOS / Manjaro

Собранный пакет — обычный файл, его можно просто переслать:

```bash
cd packaging && makepkg -f        # соберёт alchimist-world-<версия>-1-any.pkg.tar.zst
```

Получатель ставит одной командой, ничего не собирая:

```bash
sudo pacman -U alchimist-world-0.6.1-1-any.pkg.tar.zst
```

Pacman сам подтянет `pyside6` и остальное из репозиториев. В меню появится значок,
удаляется `sudo pacman -R alchimist-world`. Рабочий стол значения не имеет: KDE, GNOME,
Niri, Hyprland — одинаково.

Пакет привязан к версии Python, которой собран (код лежит в `/usr/lib/pythonX.Y/`),
поэтому зависимость записана как `python>=X.Y` и `python<X.Y+1`. На системе с другой
версией pacman честно откажется ставить — тогда пакет надо пересобрать. На одном
дистрибутиве это не всплывает.

## Своя система: любой Linux, без пакета

```bash
pipx install .
```

Или прямо из рабочего дерева: `python -m venv .venv && .venv/bin/pip install -e .`

## Отдать другому человеку

```bash
python packaging/build.py --onefile
```

Кладёт в `dist/`:

- `AlchimistWorld/` — папка с исполняемым файлом и всем необходимым;
- `AlchimistWorld-<версия>-<ос>.tar.gz` (или `.zip` на Windows) — она же в архиве;
- `AlchimistWorld-<версия>-<ос>-одним-файлом` — один файл, который просто отправить.

Внутри уже лежат Python и Qt, поэтому у получателя ничего ставить не нужно.
Вариант «одним файлом» при каждом запуске распаковывается во временную папку —
стартует на несколько секунд дольше, зато это ровно один файл.

**Собирать надо на той ОС, под которую нужен результат.** PyInstaller не умеет
собирать под чужую систему.

## Windows-сборка

### Надёжный способ: GitHub Actions

`.github/workflows/release.yml` собирает под Linux, Windows и macOS на настоящих
runner'ах. Нужен репозиторий на GitHub:

```bash
git add -A && git commit -m "Первая версия"
gh repo create AlchimistWorld --private --source=. --push   # или через сайт
git tag v0.6.0 && git push origin v0.6.0
```

Через несколько минут файлы появятся в черновике релиза. Можно и без тега —
кнопка **Run workflow** во вкладке Actions, файлы лягут в артефакты сборки.

### Быстрый способ: Wine

```bash
packaging/build-windows-wine.sh
```

Ставит внутрь Wine настоящий Windows-Python и собирает им. Получается честный
PE-файл с библиотеками Visual C++ внутри — отдельно их ставить не нужно.
Первый запуск скачивает ~200 МБ (Python и Qt), дальше использует кеш в
`~/.cache/alchimist-wine-build`.

Оговорка: собранное под Wine **не проверено на настоящей Windows**. Для того,
что отдаёте другим людям, надёжнее GitHub Actions.

## Про подпись

Сборки никем не подписаны, поэтому при первом запуске система предупредит:

- **Windows:** SmartScreen покажет «Windows защитила ваш компьютер» →
  «Подробнее» → «Выполнить в любом случае».
- **macOS:** первый запуск — правой кнопкой по значку → «Открыть».

Это не лечится ничем, кроме платных сертификатов разработчика.
